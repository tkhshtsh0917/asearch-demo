# 採用した判断

[English](../DECISIONS.md)

確定した選択の要約です。現在のAPIは[ランタイム](spec/runtime.md)が規定し、日付・詳細計測は元の証拠の範囲に限定します。

<a id="d1-compat-asearch-の既定プロファイル"></a>

## D1: 互換profile

Asearchの既定はコードポイントのasearch.ts意味論です。公開物のUTF-16動作はasearch.ts-libで明示します。

<a id="d2-一括-api-の既定の曖昧度ポリシー"></a>

## D2: 曖昧度

一括の既定はmin(floor(正規化後長/4),3)で、記述子・独自ポリシーにも上限を設けます。

<a id="d3-パッケージクレート名"></a>

## D3: 名前と責務

Rust crateはindex・builder・analyzer・engine・CLI・WASMの責務を分け、ローカルTSアダプター名はasearch-wasmを維持します。

<a id="d4-一括-api-の正規化の既定"></a>

## D4: 一括正規化

ja-basic-v1の1〜5を既定とし、互換Asearchは正規化しません。

<a id="d5-一括-api-の既定モード"></a>

## D5: 一括mode

内部wrap付きWildcardSpaceを既定にし、Exact・Includeはそれぞれの規則を維持します。

<a id="d6-ロードマップ"></a>

## D6: 段階

各段階で正しさのゲートを維持し、任意engineは同値性と効果を実測してから採用します。

<a id="d7-プロジェクトのライセンス"></a>

## D7: ライセンス

新規コア・アダプターはMIT OR Apache-2.0とし、上流原本の帰属表示を保持します。

<a id="d8-リポジトリのスコープ"></a>

## D8: 範囲

照合と結果到達時間をengineの範囲とし、UI・配信制御・学習順位は呼び出し元に置きます。

<a id="d9-索引の配信形式と更新方式"></a>

## D9: サーバー更新

不変のbase・delta・tombstoneとmanifestを使い、ネイティブのサーバー圧縮を行います。

<a id="d10-m0-の互換境界の細目asearchts-からの逸脱を含む"></a>

## D10: 互換の逸脱

観測可能な照合・変換動作を維持し、安全でない／意味のない実行時入力を意図的に拒否し、Node専用globalへの依存を除きます。

<a id="d11-初期化試行とreadyの契約"></a>

## D11: 初期化

試行ごとにreadyを1つ持ち、入力省略の並行呼び出しで共有します。失敗後は再試行でき、競合する明示初期化は拒否します。

<a id="d12-資源予算更新失敗overlay部分はd18で廃止"></a>

## D12: 資源と更新失敗

輸送・準備を含む合計容量を予約し、採用に失敗したらactive状態を維持します。

<a id="d13-bylengthの長さの定義"></a>

## D13: 長さ

正規化後・wrap前に、profile・code-point・utf16の明示単位でKを決めます。

<a id="d14-manifestの系列と適用完了状態"></a>

## D14: manifest同一性

系列内のindexId・設定を維持し、原子的採用の後だけ適用済み完全manifestを進めます。

<a id="d15-文書単位の総件数"></a>

## D15: 総数

上位件数とは独立に、生存する文書keyを最小一致level別に数えます。

<a id="d16-性能回帰の再現可能な判定"></a>

## D16: 性能判断

paired AB／BA・固定負荷・再現できる集計・再確認する回帰規則を使い、共有CIで時間閾値を設けません。

<a id="d17-文書と品質ツールの入口"></a>

## D17: 品質の入口

format・lint・型・テスト・文書を明示的で再現できるコマンドとして維持します。

<a id="d18-サーバー配信のみとしクライアント編集層を除外する"></a>

## D18: 編集層なし

サーバー配信の索引・差分だけを採用し、ブラウザのupsert・remove・forget APIは設けません。

<a id="d19-開発環境と公開用の品質設定"></a>

## D19: ツール設定

言語・依存ツールを固定し、個人パス・秘密・作業端末固有の手順を公開しません。

<a id="d20-m1の最小level-apiの境界"></a>

## D20: 最小level API

matchLevelは0..31内で最初の一致levelまたは-1を返し、明示解放は冪等です。

<a id="d21-汎用scalarwmとworkspaceの入口"></a>

## D21: 汎用スカラー作業領域

再利用するスカラーバッファを明示予約し、互換照合と資源上限付き拡張照合を分けます。

<a id="d22-単発asearchのidealプロファイル"></a>

## D22: Ideal profile

最小level engineには単調なIdeal費用を使い、互換受理は別に維持します。

<a id="d23-コーパス単位のengine境界"></a>

## D23: コーパスengine境界

不変コーパスの準備と、クエリ・作業領域・再利用する検索処理を分離します。

<a id="d24-ja-basic-v1の限定対応表と確保しない変換"></a>

## D24: 限定正規化

ホスト依存の全NFKCではなく、明示的Unicode表と確保しない変換を使います。

<a id="d25-asix-v1の圧縮と原文保持"></a>

## D25: ASIXと原文

canonicalな非圧縮ASIXと任意の原文を保持し、圧縮転送はHTTP・サーバーが担当します。

<a id="d26-説明の座標と整列"></a>

## D26: 説明

上限付きで決定的な経路復元と明示的座標系を返し、原文offsetを捏造しません。

<a id="d27-intentindex-v1の構文と資源境界"></a>

## D27: 意図DAG

上限付きparserを使い、全展開を列挙せずDAGを検索します。

<a id="d28-m7の採否とスカラー経路の改善"></a>

## D28: M7の採否とスカラー経路の改善

スカラー候補準備と共通コンパイルの改善を採用します。基本WASMを維持し、SIMD・Myers・OSA・NodeAsearchは選択可能な実装engineにしません。
