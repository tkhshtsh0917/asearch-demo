# マイルストーンと受入ゲート

[English](../PLAN.md)

## 目的

小さなRust照合・CLI・WASMリポジトリと、分離したTS／ブラウザ連携・デモリポジトリを提供します。サーバー生成のbase／delta索引を不変資産で配信し、ブラウザは検索・採用を行います。ブラウザ内の編集層やnpm公開はありません。

## 完了したマイルストーン

M0〜M7は2026-10-21にローカル受入へ到達しました。開発マイルストーンであり、現在のホスト配信状態や汎用的な性能を示すものではありません。

| ---- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| M0   | 互換コア・薄いWASM境界・JSコンパイル・初期化・型・fixture・帰属情報     | 両profile・上流fixture／例・型の形・確保検査・pack済み配布物・ブラウザ／Worker・初期化再試行 |
| M1   | matchLevel・解放・汎用ScalarWm／作業領域・コーパスengine・CLI検証／計測 | 同じ結果、JS／境界／kernelを分けた計測、paired AB／BA、集計の再現                            |
| M2   | 一括ASIX・転置blocked・正規化・曖昧度ポリシー・上位件数／総数・stream   | 独立oracle・決定的バイト列・破損／資源テスト・形式fuzz・規模検証                             |

## 全変更に共通する規則

1. 上流fixture・独立DP・engine間の比較で正しさを検査します。同じ最適化を使う実装は独立oracleではありません。
2. 確保前に型・件数・容量を検証します。更新は準備して原子的に採用し、失敗時はactive索引と適用済みmanifestを維持します。
3. Rustをunsafeなしに保ち、コピー結果／refの寿命、解放、更新の直列化を文書化します。
4. 依存・上流hash・seed・localeを固定し、pack済み配布物を独立検証します。rustfmt／Clippy、Biome、独立したTypeScript検査を実行します。
5. 性能判断には条件を制御したpaired計測を使います。共有CIの正しさ検査に不安定な時間閾値を設けず、設定予算・観測・保証を分けます。
6. 実装範囲・残ゲート・コマンド／件数・逸脱・計測条件・未検証事項を報告します。失敗runを成功に数えません。

## 公開と今後の変更

RustのRelease CIがOS別CLI／WASM Assetsをビルド・検証します。デモは検証済みタグを使い、連携／画面回帰を通して自身のworkflowで配信します。ホスト側の結果は実際のActions実行で確認し、ローカルテストだけでPages配信の証明としません。ローカル検証は自動push・タグ・npm公開を意味しません。

公開API・形式・normalizerの変更は版管理します。過去の観測を新実装の測定値へ書き換えず維持します。性能未達には、正しさを緩めず負荷・planner・予算選択を測定して対応します。
