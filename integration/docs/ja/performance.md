# API性能の比較

[English](../performance.md)

このガイドは比較の契約を説明します。コマンド・workloadの設定・レポートの項目の正本は[ベンチマークツールのガイド](../../tools/bench/README.ja.md)です。[コアの性能上の判断](https://github.com/tkhshtsh0917/asearch/blob/main/docs/ja/performance.md)は採用した最適化と条件付きの効果、[デモのガイド](../../../docs/ja/performance.md)はWorker／DOMの計測を説明します。

## 同等な成果物と入力

計測前に2つの配布物を明示的に準備し、同じASIXを使います。コンパイラー・依存と照合意味論を揃え、ソースのコミット・成果物とハーネスのハッシュ・コーパスとworkloadの識別情報・ランタイムとブラウザの情報を記録します。ソースのラベルだけでは成果物の来歴を証明できません。ビルド・テスト・別の計測を同時実行しないでください。

共通の検索設定はWildcardSpace（`mode: 2`）、`wrap: true`、正確な総数、長さに基づく編集予算（4単位ごと・最大3・profile単位・wildcardを除外）です。出力上限の既定は30で、workloadは`limit`を上書きできます。説明の準備は指定した`count`を使います。省略可能な`ranking`は`stable`・`position`を受理し、省略時は古い既定順位の成果物との互換性を維持します。両側が指定した設定に対応している必要があります。

結果のスナップショットはID・level・order・total・省略可能なstartを含み、所有者固有のopaque参照は除外します。位置順位の比較にはstartが必要です。検索・ロード検証・説明の準備は、このスナップショットと設定を共用します。レポートは両側へ実際に適用した設定を記録します。

## 計測範囲

session／全件検索の計測は、JS/WASM転送と結果コピーを含む個々の公開API呼び出しを測り、ロード・reset・HTTP・描画を除外します。ロード比較は、メモリ内の検証とexpectedのSHA-384照合を含みます。説明と短い操作のバッチは、個別打鍵のpercentileではなくバッチ平均を報告します。操作ごとの範囲と前提はツールのガイドを参照してください。

## ペア比較の解釈

AB/BAを交互に実行し、ペア実行全体を保持します。時計のゼロを残し、選択したrunのquantileがゼロなら分解能不足として比率計算を拒否します。個々の打鍵ではなくペア実行全体をbootstrapし、別のプロセス・グループで確認します。中央値付近と裾の悪化を両方確認してください。固定した入力の反復は独立したクエリ網羅ではなく、共有CIにばらつく速度閾値は設けません。

結果が違えば速度改善の主張は無効です。同じ成果物の比較はハーネスの検査で、実装改善ではありません。Rustの容量予算・WASM線形メモリ・プロセスとブラウザのRAMを分けます。エミュレーターの計測はスマホ実機の性能を保証しません。
