# スコープと用語

[English](../../spec/scope.md)

<a id="section-0"></a>

## 0. スコープ

目的はブラウザWASMでの高速な曖昧照合で、CDNからのサーバー生成索引の読み込みと、頻繁な内容更新の採用を含みます。変更は照合結果、またはロード・更新を含む結果到達時間を改善するものとします。UI・スケジューリング・ネットワーク転送・キャッシュ・個人化・学習順位は呼び出し元が担当します。

Rustは互換照合、一括／逐次／DAG照合、機械的正規化、ASIX検証、ネイティブ生成／解析、base・delta・tombstoneによる更新、サーバー側圧縮を担当します。TSアダプターはDOM非依存でWorkerでも動きます。連携用にローカルでpackし、npmには公開しません。ブラウザWASMは索引のロード・検索・採用だけを行います。形態素解析・読み・ローマ字・同義語は別のサーバー専用解析器で生成し、意図表現を自動生成しません。

当初の調整対象は合計10^5〜10^6 UTF-16単位の短いtextが中心で、10^7単位は規模検証でした。どちらも汎用的な容量保証ではありません。各textは正規化前後とも65,535 UTF-16単位以内が必須です。大きなコーパスにはtext数・単位数・作業メモリの実測予算が必要です。ブラウザ検証はスマホプロファイルを含むPlaywrightのChromium・Firefox・WebKitです。WebKitは実機Safariではなく、プロファイルはOSのIMEや実機の確認ではありません。Nodeはツール・テストに使い、Denoやエッジ実行環境は保証しません。

## 1. 用語

| 用語            | 意味                                                   |
| --------------- | ------------------------------------------------------ |
| pattern         | 利用者の検索入力。互換APIのコンストラクターのpattern。 |
| text            | 候補文字列。上流match()でqueryと呼ばれる引数。         |
| symbol          | profileに従ったUnicodeコードポイントまたはUTF-16単位。 |
| m / n           | 非ワイルドカードのpattern長／textの記号数。            |
| position i      | pattern接頭辞長0..m。ビットiはi記号消費済みを示す。    |
| level e / K     | 編集レベル／許容する最大編集レベル。                   |
| LOOPS           | 記号を無料で読み飛ばす自己ループがある位置。           |
| EQ_i(x)         | textの記号xがpattern位置iのキー集合に含まれるか。      |
| cost / level(t) | Idealの費用／K以内で最初に一致するレベル。             |
| key             | 安定したu32文書ID。更新・削除・重複排除の単位。        |
| order           | u32の順位キー。小さいほど上位で、既定はkey。           |
| segment         | サーバー生成の不変ASIXファイル。                       |
| tombstone       | 古いセグメント中の出現を無効にするkey。                |
